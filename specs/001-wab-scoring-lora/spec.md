## Clarifications

### Session 2026-05-31

- Q: 微调 5 轮逐轮评估时，用什么数据评估每一轮的效果？ → A: 不单独划验证集；5 轮微调每轮都在测试集上评估，横向对比。
- Q: 微调"成功"的吻合度门槛如何定义？ → A: 不设绝对阈值；成功判据 = 微调后模型在 MAE 与完全一致率上优于未微调 baseline。
- Q: 外部对比模型确切是哪个？ → A: 统一记作 "deepseek-v4-pro"（网络部署），与需求页/CLAUDE.md 一致；具体 API 端点/版本号留待 plan 阶段确定。

### Session 2026-06-07（v0.80 需求更新）

- Q: 新增外部对比模型 GLM 5.1 如何接入？ → A: 通过阿里云百炼（DashScope）OpenAI 兼容 API 调用（`https://dashscope.aliyuncs.com/compatible-mode/v1`），模型 ID 为 `glm-5.1`。deepseek 与 GLM 共享同一百炼端点，凭据统一经 `DASHSCOPE_API_KEY` 注入。不可用时与 deepseek 相同的优雅降级模式。
- Q: 外部推理模块如何组织？ → A: 采用统一外部推理模块（`external_infer.py`），支持多 provider 注册表；deepseek 和 GLM 共享同一套 OpenAI 兼容 HTTP 调用逻辑，通过 `--provider` 参数区分。保留 `deepseek_infer.py` 作为 thin wrapper 以保持向后兼容。
- Q: 现有 baseline 和微调结果是否受影响？ → A: 不受影响。仅新增 GLM 5.1 作为第 4 条对比路线，不修改已有推理输出、训练结果或评测数据。

## User Scenarios & Testing *(mandatory)*

本特性面向**临床 NLP 研究者**（项目所有者），目标是得到一个能依据 WAB（西方失语症成套测验）
标准、对"医生—病人"对话自动打出**信息量**与**流畅度**两个维度分（各 0–10）的微调模型，并产出
可审查的评估报告。

### User Story 1 - 构建可训练的数据集 (Priority: P1)

研究者需要把现有的真实对话转写（`datasets/conversation/P*.txt`）与 AI 合成对话（gold xlsx 的
`fakeasr` 页）转换成带金标准（信息量、流畅度分）的训练样本与测试样本，并严格按"用途"列划分
训练集 / 测试集，排除"无效"病例。每个样本的提问、图画描述、评分标准都取自 gold xlsx 的
"信息量和流畅度"页。

**Why this priority**: 没有正确构建、正确划分的数据集，后续所有微调与评估都建立在错误信号上。
这是整条流水线的地基，且可独立交付价值（一个干净、可核对的数据集本身即有用）。

**Independent Test**: 运行数据集构建步骤后，可独立核对：训练/测试样本数与"用途"列统计一致、
无"无效"病例混入、每个样本的金标准分与"打分汇总"页一致、提问与评分标准文本与
"信息量和流畅度"页逐字一致。

**Acceptance Scenarios**:

1. **Given** gold xlsx 与对话转写文件，**When** 运行数据集构建，**Then** 生成的训练集仅含
   "用途"为 `训练`/`训练FA0` 的病例、测试集仅含 `测试` 的病例，且无 `无效` 病例。
2. **Given** 某病例同时出现在对话转写与 gold xlsx，**When** 构建其样本，**Then** 该样本的
   信息量/流畅度金标准与"打分汇总"页对应行完全一致。
3. **Given** "信息量和流畅度"页的提问与评分标准文本，**When** 构建样本的 prompt，**Then**
   prompt 中的问题、图画描述、评分标准与该页内容逐字一致（不使用记忆中的摘要）。
4. **Given** 评分与理由需分两问，**When** 构建样本，**Then** 每个对话对应两类问答样本：
   一类问"信息量是几分、流畅度是几分"，另一类问"评分理由"。

---

### User Story 2 - 迭代微调模型并跟踪实验 (Priority: P1)

研究者需要用 LORA 对基座模型做微调，**迭代 5 轮**，每轮记录超参数、数据集版本与训练过程，
并在每轮结束后评估该轮效果，作为是否调整参数进入下一轮的依据。整个过程必须在单卡显存预算内
完成而不溢出。

**Why this priority**: 这是本项目的核心产出——微调后的评分模型。5 轮迭代与逐轮跟踪是需求明文
规定的关键流程。

**Independent Test**: 微调结束后可独立核对：实验跟踪记录中存在 5 轮可区分的训练记录、每轮
都有记录的超参数与对应的评估指标、训练过程未发生显存溢出、产出可加载的微调权重。

**Acceptance Scenarios**:

1. **Given** 已构建的训练集，**When** 启动微调，**Then** 完成 5 轮迭代，每轮在实验跟踪系统中
   留下独立、可追溯的记录（含超参数与数据集版本）。
2. **Given** 单卡显存预算，**When** 任意一轮微调运行，**Then** 不发生显存溢出且训练序列长度
   满足下限要求。
3. **Given** 某一轮微调完成，**When** 查看该轮记录，**Then** 能看到该轮在测试集（或留出验证）
   上的信息量/流畅度评估结果，用于与其他轮次横向对比。

---

### User Story 3 - 产出多基线评估报告 (Priority: P2)

研究者需要在测试集上对比**四路**推理输出——**微调后模型**、**未微调模型（baseline）**、**外部
对比模型 deepseek-v4-pro（网络部署）**、**外部对比模型 GLM 5.1（阿里云百炼，网络部署）**——并
产出一份 HTML 报告，逐病例列出每路的信息量分、流畅度分（及理由），并汇总与金标准的吻合度指标。
报告需放入工作目录。

**Why this priority**: 报告是验证微调是否真正带来提升的唯一可审查证据；多基线对比让结论可信。
依赖故事 1、2 的产出，故优先级次于它们。

**Independent Test**: 报告生成后可独立核对：HTML 报告可在浏览器打开、测试集每个病例都有
四路评分逐项列出、含与金标准的吻合度汇总、报告文件已存在于工作目录。

**Acceptance Scenarios**:

1. **Given** 微调模型、未微调模型与两个外部模型在测试集上的推理结果，**When** 生成报告，
   **Then** HTML 报告对测试集每个病例逐项列出四路的信息量分与流畅度分。
2. **Given** 某病例的推理输出无法被解析为有效的两维分数，**When** 处理该病例，**Then** 对其
   重跑推理，而非以缺失值或默认分静默填充；若多次仍失败则在报告中显式标注。
3. **Given** 全部推理完成，**When** 生成报告，**Then** 报告含每路模型与金标准的吻合度汇总
   （如平均绝对误差、完全一致率），供横向比较。

---

### Edge Cases

- 对话转写质量差/方言重/ASR 错误多但未被标"无效"时如何处理？——以"用途"列为唯一权威依据，
  不在本流水线内二次判定有效性。
- 病例在对话转写存在但不在"打分汇总"页（或反之）时如何处理？——缺金标准的病例不得进入任一
  数据集，并在构建日志中列出。
- 推理输出包含分数但越界（如 >10 或非整数）时如何处理？——视为解析失败，触发重跑。
- 外部对比模型 deepseek-v4-pro 网络不可用时如何处理？——记录失败并在报告中标注该路缺失，
  不阻塞微调模型与 baseline 的报告产出。
- 外部对比模型 GLM 5.1（阿里云百炼）网络不可用时如何处理？——与 deepseek 相同策略：标记
  `unavailable=true`，在报告中显式标注缺失，不阻塞其余路线。
- 单卡显存逼近上限时如何处理？——在配置阶段先评估占用，宁可降低 batch size 也不得 OOM。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 从 gold xlsx 的"信息量和流畅度"页实时读取问题文本、图画描述、
  system prompt、信息量评分标准、流畅度评分标准，用于构建样本 prompt，禁止使用硬编码摘要。
- **FR-002**: 系统 MUST 依据"打分汇总"页"用途"列划分数据集：`训练`/`训练FA0` → 训练集，
  `测试` → 测试集，`无效` → 一律排除。
- **FR-003**: 系统 MUST 将每个样本的信息量、流畅度金标准取自"打分汇总"页对应病例行。
- **FR-004**: 系统 MUST 同时纳入真实对话（`datasets/conversation/P*.txt`）与 AI 合成对话
  （`fakeasr` 页）作为训练数据来源。
- **FR-005**: 系统 MUST 将"评分"与"理由"作为两个独立问题分别提问（推理时必分两问，见 FR-010）。
  训练样本中，`score` 类必产；`reason` 类依赖可靠理由来源——`fake`(fakeasr) 病例含评分理由可直接用作
  `reason.output`，`real` 病例若无可靠理由文本则可仅产 `score` 类样本（构建日志标注）。
- **FR-006**: 系统 MUST 对基座模型执行 LORA 微调，并迭代 5 轮。
- **FR-007**: 系统 MUST 用实验跟踪系统（本地模式）记录每轮微调的超参数、数据集版本与训练过程，
  且每轮记录可独立追溯。
- **FR-008**: 系统 MUST 保证训练与推理配置在单卡 40GB 显存预算内运行而不溢出；训练序列长度
  MUST ≥ 8192，推理序列长度不设上限（仍受显存约束）。
- **FR-009**: 系统 MUST 在测试集上产出**四路**推理输出：微调后模型、未微调模型（baseline）、
  外部对比模型 deepseek-v4-pro（网络部署）、外部对比模型 GLM 5.1（阿里云百炼，网络部署）。
- **FR-010**: 系统 MUST 将每路推理输出解析为结构化的信息量分与流畅度分；解析失败的病例
  MUST 重跑推理，不得静默填充缺失或默认值。
- **FR-011**: 系统 MUST 产出 HTML 测试报告并存入工作目录，报告 MUST 逐病例列出四路的详细评分
  （信息量、流畅度及理由），并 MUST 汇总各路与金标准的吻合度指标。
- **FR-012**: 系统 MUST 逐轮评估微调效果，使各轮的参数与效果可横向对比。
- **FR-013**: 系统 MUST NOT 单独划分验证集；5 轮微调每轮均直接在测试集上评估，用于轮次间横向
  对比（数据量小，独立验证集会进一步稀释训练信号）。
- **FR-014**: 系统 MUST 按信息量、流畅度两维分别计算下列吻合度指标，并给出总体汇总；指标
  分两类：
  - **吻合度类**（逐病例聚合）：相关性（Spearman 与 Pearson）、QWK（二次加权 Kappa）、
    完全一致率（Exact Match）、±1 容忍准确率（Off-by-one）、MAE、RMSE。
  - **运营类**（流程健康度）：首次推理解析成功率、重跑后最终仍失败的病例数。
  系统 MUST 对微调后模型、未微调 baseline、deepseek-v4-pro、GLM 5.1 四路各自计算上述指标以供横向对比。
- **FR-015**: 系统 MUST 采用统一外部推理模块（`external_infer.py`）处理 deepseek-v4-pro 与
  GLM 5.1 两路外部模型，通过 OpenAI 兼容 HTTP API 调用；外部模型凭据均经环境变量注入（
  `DEEPSEEK_BASE_URL`/`DEEPSEEK_MODEL` 与 `GLM_BASE_URL`/`GLM_MODEL`），两者共享 `DASHSCOPE_API_KEY`，
  deepseek API key 回退到 `DASHSCOPE_API_KEY`。不得硬编码或入库。
  默认端点均为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。

### Key Entities *(include if feature involves data)*

- **病例 (Case)**：一次 WAB 评估，标识为病例编号（如 P001）。属性：对话转写文本、信息量金标准
  分、流畅度金标准分、用途标签（训练/训练FA0/测试/无效）、语言、来源（真实/合成）。
- **评分标准 (Scoring Criterion)**：信息量与流畅度各自的 0–10 分判定规则及问答正确性规则，
  权威来源为 gold xlsx"信息量和流畅度"页。
- **训练样本 (Training Sample)**：由病例对话 + prompt（含问题/图画描述/评分标准）+ 目标输出
  （评分 或 理由）构成的一条微调数据，分"评分"与"理由"两类。
- **微调轮次 (Tuning Iteration)**：5 轮迭代中的一轮，关联其超参数、数据集版本与评估结果。
- **推理结果 (Inference Result)**：某路模型对某病例的输出，解析后含信息量分、流畅度分、理由、
  解析是否成功的标记。`model_route` 枚举：`finetuned` / `baseline` / `deepseek` / `glm`。
- **评估报告 (Evaluation Report)**：测试集上四路推理的逐病例明细 + 吻合度汇总，HTML 形式。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 数据集划分与"打分汇总"页"用途"列统计 100% 一致，且 0 个"无效"病例混入任一数据集。
- **SC-002**: 每个训练/测试样本的金标准分与"打分汇总"页对应病例 100% 一致。
- **SC-003**: 微调完成 5 轮，且实验跟踪系统中存在 5 份可区分、含超参数与评估结果的轮次记录。
- **SC-004**: 训练与推理全过程 0 次显存溢出。
- **SC-005**: 测试报告中，测试集每一个病例都有微调后模型、未微调模型、deepseek-v4-pro、GLM 5.1
  四路的信息量分与流畅度分（外部模型不可用时显式标注缺失，不计入"未列出"）。
- **SC-006**: 推理输出无最终未解析的病例——所有解析失败都经过重跑，最终要么解析成功，要么在
  报告中显式标注为多次重跑后仍失败。
- **SC-007**: 报告给出四路模型（微调后 / 未微调 baseline / deepseek-v4-pro / GLM 5.1）各自与
  金标准的吻合度指标，按信息量、流畅度两维分列并附总体汇总。指标至少包含：相关性（Spearman、
  Pearson）、QWK、完全一致率、±1 容忍准确率、MAE、RMSE，以及运营类的解析成功率与重跑后最终
  失败数；可直接横向比较微调前后及与两个外部模型的差异。
- **SC-008**: HTML 报告文件存在于工作目录且可在浏览器正常打开浏览。
- **SC-009**: 微调被判为成功，**首要判据**为微调后模型与金标准的**相关性**（Spearman/Pearson）
  高于未微调 baseline；**次要指标**为 QWK 高于 baseline（用于在相关性接近时区分优劣）。其余
  指标（完全一致率、±1 容忍准确率、MAE、RMSE）作为参考。不设绝对数值阈值，判定为相对 baseline
  的改善。外部模型（deepseek-v4-pro、GLM 5.1）不参与此成功判定。

## Assumptions

- "用途"列是数据集有效性与划分的唯一权威依据；本流水线不在其之外二次判定病例有效性。
- gold xlsx 的当前版本（v0.80）为本轮工作的金标准版本；版本变更需重新构建数据集。
- 微调与推理均在已确认的单卡 A100 40GB 环境上执行（见 constitution 的硬件约束）。
- 外部对比模型 deepseek-v4-pro 通过网络访问，可能因网络/配额不可用；其缺失不阻塞其余产出。
  具体 API 端点/版本号在 plan 阶段确定。
- 外部对比模型 deepseek-v4-pro 与 GLM 5.1 均通过阿里云百炼 DashScope OpenAI 兼容 API 访问
  （端点 `https://dashscope.aliyuncs.com/compatible-mode/v1`），共享 `DASHSCOPE_API_KEY`；
  token 计划付费；凭据经环境变量注入，不可用时优雅降级。
- "信息量"与"流畅度"是本特性范围内的两个评分维度；理解/复述/命名/AQ 等其他 WAB 维度不在范围内。
- "check-in 到仓库"指将报告等产物放入本工作目录（仓库即工作目录）。
